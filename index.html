Shannon Entropy & Brute Force Estimations

Password entropy measures strength in bits. It answers: "How many binary questions does an attacker need to ask to guess the password?"

Entropy (E) = Length (L) × log₂ (Character Pool Size R)

Each added character multiplies the potential password space exponentially. If an attacker runs a GPU cluster trying 100 billion keys per second (10¹¹ H/s):

  • Under 50 bits (Weak): Guessed in minutes or hours.
  • 60 - 80 bits (Moderate): Secure for everyday personal user logins.
  • Over 100 bits (Cryptographically Strong): Takes millions of years to crack, offering ultimate safety against server database dumps and parallel brute-force attacks.

Why Do We Hash Passwords?

Secure websites **never** store plain text passwords. Instead, they use a one-way mathematical function called a Cryptographic Hash (e.g. SHA-256 or bcrypt) to turn your password into a unique fixed-length string of hex characters.

  • Preimage Resistance: It is mathematically impossible to reverse a high-quality cryptographic hash to obtain the plain text password.
  • Deterministic: The same password always results in the exact same hash. So, when you log in, the server hashes your input and matches it with the stored hash.
  • Salt Protection: Modern servers add random strings ("salts") to passwords before hashing to make offline precomputed tables ("rainbow tables") useless.
